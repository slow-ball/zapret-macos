# Как устроен zapret для macOS

Для тех, кто хочет поправить код или понять, что происходит на маке. Как пользоваться — в [README](README.md).

## Три части

```
zapret.app (SwiftUI)  ──sudo -n──▶  zapret.sh (bash)  ──launchd──▶  run.sh ─▶ utunws (движок, C)
  окно, панель, виджет              вся логика: старт,               pf заворачивает трафик в utun,
  только показывает и просит        стратегии, подбор,               движок меняет пакеты и отправляет
                                    обновления, DNS, Telegram         их сам на сетевой интерфейс
```

- **Скрипт** (`src/zapret.sh` + `src/lib/*.sh`) — единственное место, где принимаются решения.
  `zapret.sh` только разбирает команду и подключает модули; каждый модуль — одна тема
  (`nfqws.sh` — движок, `sites.sh` — умный режим, `update.sh` — обновления и т. д.).
  Команды работают одинаково из терминала (`zapret.command`), из приложения и из launchd.
- **Приложение** (`app/Sources`) ничего не делает с системой само: зовёт скрипт через `sudo -n`
  (правило в `/etc/sudoers.d/zapret-macos` ставит `install_sudoers`, только нужные команды)
  и читает `zapret.sh status --json`. Модель — `AppModel` (`Model*.swift` по темам),
  экраны — `Home`, `StrategiesPage`, `SitesPage`, `DiagnosticsPage`, `Settings`, `Journal`, панель строки меню — `MenuPanel`.
- **Движок** (`engine/`) — наш форк utunws, порта nfqws для macOS. Откуда он и что в нём своего —
  [engine/README.md](engine/README.md). Собирается `build/utunws.sh`.
- **Адаптивная стратегия** — лестницы приёмов в движке (`engine/nfq/ladder.c`): TCP, QUIC и голос Discord.
  Сайт поднимается на следующий приём при сбое (сброс, заглушка, тишина), а движок сам мерит скорость по
  подтверждениям браузера и переводит сайт на заметно более быстрый приём. Сторож (`service.sh`) добавляет то,
  чего движок не видит: обрыв страницы на середине у частых сайтов, обучение порядка и генератор новых приёмов.
- **Прокси для Telegram** (`engine/tg/main.swift`, `zapret-tg`) — свой, без Python: MTProto с dd-секретом,
  до Telegram — WebSocket к его веб-серверам, через посредников на Cloudflare или напрямую к дата-центру.
  Собирается вместе с движком; тем же бинарником сделаны проверки `telegram test` и голоса Discord (STUN).

## Что лежит на маке

| Где | Что |
|---|---|
| `/opt/zapret-macos` | копия скриптов и движка, принадлежит root: launchd и приложение зовут только её |
| `/opt/zapret-macos/current` | стратегия, которая работает сейчас |
| `/opt/zapret-macos/lists/list-auto.txt`, `site-strategies` | найденные умным режимом сайты и стратегии для отдельных сайтов |
| `/Library/LaunchDaemons/com.zapret-macos.*` | движок (`nfqws`), сторож (`watchdog`), прокси Telegram (`telegram`) |
| `/var/log/zapret-macos.log` | журнал, его показывает страница «Журнал» |
| `~/zapret-macos` | папка проекта пользователя: свои списки сайтов, отсюда `zapret.command` |

Пользовательские файлы root читает и дописывает только через `user_cat` / `user_append`, с правами
владельца папки: иначе ссылка в папке пользователя дала бы любой программе доступ к системным файлам.

## Как идёт трафик

1. `run.sh` (launchd, `com.zapret-macos.nfqws`) поднимает utun и правила pf в якоре
   `com.apple/zapret-macos`: исходящий трафик программ пользователя (не root) уходит в utun.
2. utunws применяет стратегию (файл в формате nfqws, `src/nfqws/*.conf`) и отправляет пакеты сам,
   через BPF на физический интерфейс.
3. В умном режиме (`ZAPRET_INBOUND=1`) движок ещё и читает ответы серверов (`engine/nfq/macrecv.c`):
   сброс или переадресация на страницу блокировки — и сайт попадает в `list-auto.txt`.
4. При смене сети или после сна `run.sh` перезапускает движок для новой сети (SIGUSR1),
   при смене стратегии — только движок (SIGHUP).

## Стратегии

- `src/nfqws/strategies.tsv` — из Windows-версии, обновляются workflow Import strategies (`strategies.yml`, раз в день).
- `src/nfqws/macos.conf` — свои; ступени адаптивной сверх них — `ladder-extra.conf`, для QUIC и голоса —
  `ladder-quic.conf` и `ladder-voice.conf`; новые приёмы делает генератор (`auto_ladder_evolve`, `service.sh`).
- Фейковые пакеты (`src/nfqws/bin`) — свои: `build/fakes.swift` делает ClientHello, QUIC Initial (RFC 9001) и
  STUN по именам файлов, на которые ссылаются стратегии; одинаковые байты при каждой сборке.
- Свежие пакеты стратегий без релиза — `src/lib/pack.sh`, собирает workflow Strategy pack (`pack.yml`), подписаны своим ключом.
- Подбор (`check`), глубокий поиск (`deep`) и стратегии для отдельных сайтов (`learn`) — `check.sh`, `sites.sh`.

## Обновления и подписи

Обновления приходят только из релизов. Архив релиза подписан ключом проекта (`build/release.sh`,
`ssh-keygen -Y sign`); скрипт и приложение принимают только подписанные архивы — открытые ключи
в `src/zapret.sh` (`RELEASE_KEY`, запасной `RELEASE_KEY_BACKUP`). Приложение само сверяет
`/opt/zapret-macos` с подписанным релизом (`Integrity.swift`).

| Что | Где | Когда |
|---|---|---|
| модули скрипта | `tests/unit.sh` | Check, `build/ship.sh` |
| логика приложения | `tests/AppTests.swift` | Check, `build/ship.sh` |
| переводы (у каждой строки есть, лишних нет), импорт стратегий | `tests/test_*.py`, `build/l10n.py --check` | Check |
| фильтр входящих пакетов движка | `tests/engine_filter.*` | Check |
| лестница движка: ключи сайтов, подъём, живой выбор, файлы | `tests/engine_ladder.c` | Check |
| фейки — свои и разбираются парсерами движка | `build/fakes.swift --check`, `tests/engine_fakes.c` | Check |
| shellcheck | `check.yml` | Check |
| стиль Swift (swift-format, правила в `.swift-format`) | `check.yml` | Check |
| все экраны рисуются, светлая и тёмная тема (снимки — в артефактах прогона) | `check.yml` | Check |
| весь путь пользователя на настоящем macOS | `e2e.yml` | каждый push |

CI работает на Intel (`macos-15-intel`): маки на Apple Silicon у GitHub для бесплатных аккаунтов
почти не бывают свободны.

## Переводы

Тексты пишутся по-русски прямо в коде. Английский: для скрипта — `src/lang/en.tsv`, для приложения —
`app/l10n/en.py`. Проверки падают, если у строки нет перевода или перевод остался от удалённой строки.
Комментарии в коде — по-английски.

## Выпуск

`build/ship.sh X.Y.Z` из ветки с готовой работой (в `CHANGELOG.md` и `CHANGELOG.en.md` уже есть
раздел версии): поднимает версию, ждёт CI, собирает движок и приложение (workflow Build, `utunws.yml`),
закрепляет их в `src/zapret.sh`, переносит ветку в main, публикует релиз с `zapret.dmg`,
подписывает архив и обновляет cask в Homebrew. Остановился — повторный запуск продолжит с того же шага.
Ветку называть не как тег (`v1.1`, а не `v1.1.0`). Ветка, которая меняет движок, сначала собирает его
(`utunws.yml` со следующим номером) и закрепляет в `src/zapret.sh`: E2E скачивает закреплённый.
